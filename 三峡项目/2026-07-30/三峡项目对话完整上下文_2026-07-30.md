## 10. 隔离数据原则

为避免污染三峡环境存量数据，本轮采用唯一业务流水号、客户编号、客户名称等隔离键。

关键原则：

- 每条用例使用唯一 `S_S_BIZID`
- 每条规则命中用例使用唯一 searchKey
- 不复用可能命中存量三方数据的客户键
- 写入前核对真实表结构和 SQL 查询键
- 写入后立即回查
- 测试结束后按本轮唯一标识清理
- 清理后逐表验证残留数量

## 11. 24 条异常用例

“24 个异常案例会被有意拦截，直到提供真实 mock 环境”的含义：

- 这些用例不是普通的业务正例或反例
- 它们用于验证超时、连接失败、第三方返回错误码、响应格式非法、缺字段、空响应等技术故障
- 仅修改 MySQL 正常业务数据无法真实模拟这些异常
- 如果把普通请求伪装成异常用例，可能出现“策略执行成功但并未测试异常处理”的假通过

因此 `tiance-policy-test` Skill 要求：

- 异常用例声明 `executionMode=mock`
- 声明具体 `mockScenario`
- 配置中存在对应 mock 契约
- mock 服务真实启用
- 运行前探针生成有效 readiness 证明
- readiness 失败时阻断异常用例

## 12. 策略测试 Skill 当前标准

当前 `tiance-policy-test` Skill 的主流程：

```text
会话检查
→ 平台门禁
→ 策略版本和业务类型校验
→ 语义/mock 预检
→ 隔离 Fixture
→ 单笔执行
→ 规则/函数/三方节点结构化证据比对
→ 15 列 Excel 报告
→ Fixture 清理
```

关键门禁：

- 每次测试前从平台核对 `policyVersion` 和 `businessType`
- 禁止凭历史值或本地缓存直接提交
- `S_S_BIZID` 必填
- 三方 SQL 中的 `#{变量}` 必须有对应系统字段
- 正常用例和异常 mock 用例分开
- `runStatus=2` 不能直接判定测试通过
- 报告状态依据规则、函数和三方节点证据判定
- 测试数据必须可清理、可回查、不可污染存量

## 16. 元数据正式流程

正式流程必须按以下顺序执行：

1. 检查已有登录 tab 的实际 `location.origin`
2. 选择空闲 receiver 端口
3. 读取并执行 `capture-init.js`
4. 调用 `window.__previewCaptureIdentity()`
5. 展示并确认：
   - 实际 origin
   - 当前用户
   - 当前机构
   - 角色
   - 授权应用
   - 输出目录
   - A-M 拉取范围
6. 确认后才启动 receiver
7. 调用 `window.__assertCaptureIdentity()`
8. 依次读取并执行 `category-a.js` 至 `category-m.js`
9. 读取并执行 `transfer.js`
10. 轮询 `window.__captureTransferState`
11. receiver `/finalize` 密封 raw 和 receipt

### 影响

Skill 的身份和采集脚本依赖：

```javascript
sessionStorage.getItem("_csrf_")
```

所有天策 API 请求需要：

```http
X-Cf-Random: <sessionStorage._csrf_>
```

平台认证同时依赖：

- 浏览器会话 Cookie
- `X-Cf-Random` CSRF 请求头

即使页面已经登录，如果自动化请求无法读取并携带 CSRF，请求仍会返回 `401`。

### Codex 与 QoderWork 的差异

Codex Browser Use：

- 使用隔离、安全裁剪的执行环境
- 与页面共享可见 DOM
- 不暴露页面主环境中的 `sessionStorage`、`localStorage`、`fetch`
- 无法直接运行当前 Skill 的 main-world 采集脚本

QoderWork `javascript_tool`：

- 在页面 main world 执行
- 与 DevTools Console 中执行代码基本等价
- 可以访问 `sessionStorage._csrf_`
- 可以访问页面 `window` 变量和原生 `fetch`
- 可以直接执行 `capture-init.js`、A-M 类别脚本和 `transfer.js`

结论：

当前元数据 Skill 是按 QoderWork main-world JavaScript 能力设计的。在 Codex 中需要人工 DevTools Console 中转，或者为 Skill 增加兼容 Codex 的主世界执行通道。
